# Project Engineering Rules

- Keep feature-flag reads centralized and enforce the same flag in navigation and route guards so disabled modules cannot be opened by URL.
- Multi-table project setup imports use one authenticated database RPC transaction so validation, upserts, and audit rows commit or roll back together.
- Contract-labour attendance and master changes use dedicated role- and project-checked database functions, keeping employee GPS attendance and payroll data outside the module.
- Daily site reports reuse daily_measurements (trade='daily_site_report') and write only through role- and project-checked SECURITY DEFINER RPCs, so existing measurement RLS stays untouched; construction tasks are marked by project_tasks.work_category because task_type is an existing enum.
- Daily-report elevation photos use kind='elevation' + elevation_id via add_site_report_elevation_photo; legacy fixed kinds stay valid for old rows, and project_elevations changes go only through role-checked RPCs with their own log table.
- Daily Report quantities use site_report_quantities through checked RPCs; measurement_line_items keeps its legacy boq_items foreign key so legacy sheets remain compatible.
- Legacy measurement notification triggers must return early for trade='daily_site_report' so report submission and re-submission cannot generate factory measurement alerts.
- Expense receipts live in the private expense-receipts bucket (<user_id>/<yyyy-mm>/<file>), shown via signed URLs; policy checks are stored warnings with a reason, never hard blocks, and cross-user duplicate checks go through a SECURITY DEFINER RPC so expense_entries RLS stays unchanged.
- Expense Excel template and reader share one column list (src/lib/expense-excel.ts) and the reader locates the header by the Date cell, so template and parser cannot drift.
- Reminders run in PostgreSQL only; one event per subject/level retains all role-resolved recipients in recipient_ids to preserve uniqueness while delivering one summary per recipient per run.
- Escalation limits are enforced by update_escalation_level and mirrored in reminder-validation for immediate feedback; server validation remains authoritative.
- Tier 1 business access uses TIER1_ROLES and is_tier1/is_tier1_or_super; reviewed legacy rewrites require parity2_backup originals and atomic rollback, while sensitive definitions remain excluded to preserve their review boundary.
- Edge director access mirrors frontend TIER1_ROLES in _shared/director-tier.ts with a parity test; recipient helpers deduplicate auth user IDs because role-query joins may return the same person more than once.
- External exports use a fixed versioned column manifest, service-only hourly-rate projection, and private exports bucket; dashboard tokens are hashed and audited, and can sign only latest manifest files because source credentials and unrestricted storage access must never reach clients.
- Measurement header WIP lives in finance-only daily_measurement_wip; legacy header fields remain neutral, checked writers update the private table, and service exports join it without changing the versioned CSV schema.
- Site readiness detail lives in site_readiness_checks/tolerances/crane/crane_cost with policies via can_read/can_write_site_readiness helpers mirroring site_readiness; tolerance auto-flag rules live in src/lib/site-readiness-foundation.ts and site_readiness_validate_check() and must stay in sync.
- Subcontract rates reuse labour_contractors and are written through checked Setup/Project Rates RPCs (deactivated, never deleted); shared audit triggers log both paths, while Daily Report subcontract snapshots preserve history.
- Contract-labour attendance needs a same-day live-camera toolbox photo (add_attendance_photo, private attendance-photos bucket); earlier days without a photo go only through the logged no-photo exception in save_labour_attendance, and evening hours are confirmed via confirm_labour_hours, which submit_site_report checks.
- Running Bill is read-only and computed by get_running_bill (role-checked via can_view_running_bill) from submitted, non-archived daily site reports up to an as-of date; the legacy RunningBillTable/recalc_running_bill stay in code but are no longer shown.
- Running Bill caps earned quantities only for positive BOQ quantities and reports excess separately; scope changes serialize and flush captured Daily Report saves before loading another report to prevent lost or misdated edits.
- Daily Report task workers are saved only through the checked draft RPC, derive legacy task hours, and allocate Running Bill costs exactly; historical reports keep proportional allocation.
- Daily Report consumables and site expenses use an audited full-list draft RPC with archival replacement and project-scoped reads, keeping employee expenses separate.
- Navigation-permission rows are scoped to assigned user_roles; Tier 1/Super retain the cross-role editor, while module-menu logic remains unchanged to preserve screen parity.
- Site report subcontract snapshots have safe-column-only direct grants; checked commercial paths expose monetary fields, while site report validation receives only matching/package metadata to prevent cost disclosure without breaking quantities.
- Record corrections use fixed typed statements and caller-bound role checks, preserving record owners, reporting-manager relationships and the 48-hour submitter window to avoid dynamic-command escalation.
- Account password mutations use the checked account endpoint and shared fingerprint-based policy; mandatory-change flags clear only after Auth succeeds, and authenticated screens stay unmounted until the flag is checked.
- Account role changes use a service-only serialized, audited RPC replacing all target role rows and synchronizing the profile mirror; server grants use user_roles and protect self changes and the last active Super Admin.
- Generated account credentials remain only in transient responses and screen state, cleared on dismissal; bulk creation exposes a CSV download without audit-log or persistent client storage copies.
- Scoped machine functions use the generated cron authenticator with a validated Tier 1/Super manual fallback; legacy unmarked schedules cannot be tightened until header migration or interruption is explicitly resolved.
- Scoped user functions authenticate against user_roles and resolve record projects server-side before privileged work; email user input enters escaped server templates and notification flags are caller-owned.
- Factory attendance is isolated in factory-specific records and reuses the live camera and shared shift setting; never represent the factory as a projects row because it would contaminate project lists and reporting expectations.
- Factory reports use checked full-list RPCs, archived replacement, private attendance-rate snapshots and module/stage allocation; source-linked production logs preserve history without changing module stages.
- New factory role gates read caller-bound user_roles, not legacy profile role mirrors; monetary snapshots have no direct authenticated column grants and cost access uses checked RPCs.
- Running Bill unions submitted site/factory quantities before the existing positive-BOQ cap, while factory labour remains a separate exact-allocation section and legacy site cost CTEs remain unchanged.
- Factory nightly exports use the shared versioned manifest with operational attendance hours only, excluding worker wage amounts and rate fields, so private cost snapshots never enter factory CSV projections.
- Today is a company-wide read-only Site Hub exception to project selection, using the existing site_report flag and a caller-bound overview RPC; existing project tabs retain their guard and permitted costs are aggregate-only.
- Project Rates uses the unchanged project_setup flag and can_view_running_bill gate; Excel keys resolve project+sno against the latest BOQ and revalidate atomically at Confirm, preventing stale-version imports.
- Material quantity snapshots capture once through submit-only helpers, distinguish uncaptured legacy NULLs from missing rates, and suppress amounts when an active contractor rate includes material; explicit safe column grants keep rates/amounts RPC-only and outside nightly exports.
